How the OAuth Flow Works
1
User clicks Connect
Frontend hits /auth/x → server calls X to get a request token → redirects user to twitter.com/oauth/authorize
2
User approves on X.com
X shows your app name + requested permissions. User clicks Allow.
3
X calls your Callback URL
X redirects to /auth/x/callback?oauth_token=…&oauth_verifier=…
4
Server exchanges for Access Token
Your api/auth-callback.js trades the verifier for a permanent access_token + access_token_secret and saves them.
5
Post tweets anytime
POST /api/tweet looks up the stored token and calls api.twitter.com/2/tweets on the user's behalf.
Environment Variables (Vercel Dashboard)
# From developer.x.com → Your App → Keys and Tokens
X_API_KEY=your_api_key_here
X_API_SECRET=your_api_secret_here
# Your Vercel URL + /auth/x/callback
CALLBACK_URL=https://your-app.vercel.app/auth/x/callback
Deploy steps:
  • 1Push this folder to a GitHub repo
  • 2Go to vercel.com → Import → select your repo
  • 3Add the 3 env vars above in Vercel's Settings → Environment Variables
  • 4Copy your Vercel URL and paste https://your-app.vercel.app/auth/x/callback into X Developer Console → Callback URI
  • 5Set App Permissions to Read and Write in the X Developer Portal
  • 6Click Connect above and test!
